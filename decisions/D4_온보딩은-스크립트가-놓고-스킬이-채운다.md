## D4. 온보딩은 스크립트가 놓고 스킬이 채운다 (2026-09-09)

**변경.** greenfield 온보딩을 둘로 갈랐다.

| | 누가 | 답하는 것 | 검증 |
|---|---|---|---|
| 놓기 | `scripts/apply-template.mjs` | **무엇이 있어야 하는가** | 목록이 코드에 있다. 회귀 15건 |
| 채우기 | `skills/harness-init` | **무엇을 적어야 하는가** | 없다 → 산출물에 판정을 건다 |

그리고 선택 디렉터리 둘을 `--with old,reference` 로 붙였다.

**근거.** 스킬은 검증 가능한 산출물을 못 낸다 — 모델이 파일 하나를 빠뜨려도
조용하고, 몇 달 뒤 "왜 이 프로젝트는 게이트가 안 도나" 로 돌아온다. 반대로
스크립트는 "무엇을 만드나" 같은 자유 서술을 못 쓴다. **경계를 이렇게 그으면
각자 자기가 검증할 수 있는 것만 맡는다.**

기존 `codebase-onboarding`·`/project-init` 은 둘 다 **코드가 이미 있는**
저장소를 분석한다. greenfield 는 아무도 안 한다. 겹치지 않는다.

### 이 설계의 최대 위험과 대책

**에이전트가 골격을 그럴듯한 거짓으로 채운다.** `STATUS.md` 의 「도는 것」에
계획을 사실처럼 적으면 그 문서는 **낡은 것보다 나쁘다** — 처음부터 틀렸는데
사실로 읽힌다. 그래서 템플릿이 채우는 칸과 **채우면 안 되는 칸**을 미리
갈라 놓고, 스킬이 그것을 표로 다시 못 박는다.

같은 이유로 **`RUNBOOK.md` 에 적는 명령은 한 번씩 실제로 돌린다.** 안 돌면
적지 않는다. 안 도는 명령이 적혀 있으면 다음 세션이 그걸 믿고 시간을 태운다 —
낡은 지도보다 나쁜 것이 틀린 지도다.

완료 판정은 넷이고 둘은 기계다: `gates-report` 0 · `budget` 0 ·
RUNBOOK 명령이 실제로 돌았음 · STATUS 「도는 것」이 정직함.
**첫 커밋이 곧 시험이다** — 문서를 부풀리면 예산 검사에서 막힌다.

### `old/` 와 `Reference/` 를 한 규약으로 묶지 않았다

| | `old/` | `Reference/` |
|---|---|---|
| 무엇 | 이 프로젝트의 과거 기획 | 외부 재료 |
| 수명 | 옮기고 **지운다** | 계속 둔다 |
| git | **넣는다** — 옮긴 흔적이 diff 로 남아야 한다 | **뺀다** — 인덱스만 커밋 |
| 위험 | 두 벌의 진실 | 남의 결론을 규칙으로 물려받음 |

`Reference/` 의 위험은 `README.md` 가 이미 경고한 것과 같다: *남의 결론을
규칙으로 물려주면 외부 배포판을 그대로 받는 것과 같은 실수*. 그래서
**재료지 근거가 아니다** — 보고 정했으면 `decisions/` 에 자기 말로 적는다.

git 에서 뺀 이유는 남의 산물·이미지가 저장소를 부풀리고 저작권이 딸려 오기
때문이다. **인덱스만은 커밋한다** — 무엇을 보고 정했는지는 남아야 하고,
다른 사람 체크아웃에는 실물이 없으므로 출처를 표에 적게 했다.

### 하네스로 되먹이는 경로를 뚫었다

템플릿 밖 파일은 사람 승인을 받되, **같은 이유가 두 번째면 템플릿이 틀린
것**으로 본다. 그때는 파일을 더 만들지 말고 `template/` 에 넣고
`apply-template` 의 `FILES` 에 한 줄 더한다. 지금까지 **프로젝트 → 하네스
피드백 경로가 아예 없었다.** 이 저장소의 "같은 도구 실패가 두 번째면
결정이다" 와 같은 구조다.

**뒤집힐 조건.**

- 온보딩 세션이 끝났는데 `gates-report` 나 `budget` 이 0 이 아닌 채로
  넘어가는 일이 반복되면, 판정이 절차에 안 박힌 것이다. 스킬이 아니라
  **스크립트가 판정을 강제하는 쪽**으로 옮겨야 한다
- `--with` 옵션을 매번 켜게 되면 그건 옵션이 아니라 기본값이다
- 되먹임(`template/` 에 항목 추가)이 **한 번도 안 일어나면** 그 경로가 죽은
  것이다. 죽었으면 규칙을 지우고 다른 방법을 찾는다

**관련.** [[D3_학습은-관측만-켜고-승격은-손으로-한다]] — 자동 승격을 거부한
것과 같은 이유로, 온보딩도 사람 승인을 거친다.
