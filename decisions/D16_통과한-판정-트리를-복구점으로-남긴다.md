## D16. 통과한 판정 트리를 복구점으로 남긴다 (2026-09-27)

**변경.** `done.mjs F<n>` 이 **통과하면** 그 판정이 본 워킹트리(D11 이 이미 해시한 것)를
`refs/worktree/harness/green` 에 건다. `done.mjs --green` 이 그 트리와 되돌리는 명령을 말한다.

```bash
git restore --source=refs/worktree/harness/green --staged --worktree -- .
```

추적되는 파일이 그 상태로 돌아가고, 그 뒤에 더한 파일은 지워지고, 추적 안 된 파일은 남는다.
실패한 판정은 복구점을 옮기지 않는다. 되돌리기를 **자동으로 하지 않는다** — 명령만 준다.

**근거.**

*에이전트가 이상하게 했을 때 돌아갈 곳이 git 커밋뿐이었다.* 커밋은 에이전트가 **언제
하느냐**에 달렸고, 커밋 사이의 "마지막으로 판정이 통과한 상태" 는 어디에도 없었다.
그런데 D11 이 이미 판정마다 워킹트리를 트리 객체로 만들고 있었다. 이름 하나만 붙이면
복구점이다 — 새 상태를 만드는 것이 아니다.

*ref 로 붙잡는다.* 판정 기록의 트리는 아무 ref 도 안 가리켜 `git gc` 가 언젠가 지운다.
복구점 하나만은 지워지면 안 된다. `refs/worktree/` 는 워크트리마다 따로라 병렬 작업이
서로의 복구점을 덮지 않는다.

*"통과" 가 기준이다.* D11 은 돌았는지만 보지만, 되돌아갈 곳은 **맞았던** 곳이어야 한다.

*자동으로 되돌리지 않는다.* 워킹트리의 변경을 버리는 일이다. 무엇을 버릴지는 사람이
정한다(D13 과 같은 이유 — 되돌리기 어려운 일은 사람에게).

**버린 대안.**

| | 왜 버렸나 |
|---|---|
| 판정마다 자동 커밋·브랜치 | 히스토리를 에이전트 리듬으로 채운다. 커밋은 사람이 읽는 단위다 |
| `git stash create` 로 스냅샷 | 추적 안 된 새 파일을 안 담는다. 에이전트가 만든 파일이 빠진다 |
| 복구점을 여럿 남긴다 | 어느 것으로 돌아갈지 고르는 일이 생긴다. 필요해지면 늘린다 |

**뒤집힐 조건.**

- 되돌린 뒤 **한 칸 더 전**이 필요했던 일이 관측되면 복구점을 여럿 둔다
- 복구점이 **한 번도 안 쓰이면** 명령을 RUNBOOK 에서 내린다(기능은 싸니 둔다)
- 판정 명령이 파일을 만들어 트리가 바뀌는 프로젝트에서는 복구점이 판정 **전** 상태다 —
  그게 맞지만, 헷갈림이 관측되면 출력에 적는다
