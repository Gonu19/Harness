## D11. 완료 판정은 Stop 훅이 묻는다 — 결과가 아니라 돌았는지, 한 번만 (2026-09-27)

**변경.** D8 의 "기능이 끝났다고 말하기 전에 판정 명령을 돌린다" 를 게이트로 올린다.

| 부품 | 하는 일 |
|---|---|
| `scripts/done.mjs <F#>` | PRD 판정 칸의 첫 백틱을 돌리고, **돌리기 전 워킹트리 해시**와 종료 코드를 `<git-dir>/harness/done.jsonl` 에 덧붙인다 |
| `session-baseline` (SessionStart) | 세션 시작 트리 해시를 한 번 남긴다 |
| `stop-check` (Stop) | 이 세션에서 `.md` 아닌 파일이 바뀌었는데 **지금 트리**의 판정 기록이 없으면 막는다 |

막는 것은 턴당 **한 번**이다(`stop_hook_active`). 판정 명령이 있는 기능이 PRD 에
없으면 소관이 아니다. `gates-report` 는 QA 줄에 이 게이트를 센다.

**근거.**

*문서 규칙은 스스로 집행하지 않는다.* D6 은 같은 규칙을 한 세션에 세 번 어긴
기록이고, D9 는 문서가 네 번 낡은 기록이다. D8 의 뒤집힐 조건이 "판정이 돌려지지
않은 채 끝났다가 반복되면" 이었다 — 그걸 기다리지 않은 이유는 **반복됐는지 알
수단이 없어서**다. 안 돌린 것은 조용하다.

*결과가 아니라 돌았는지.* Stop 은 기능이 끝날 때만이 아니라 **턴마다** 발화한다 —
중간 보고, 사람에게 묻기. 그때 판정이 실패하는 건 정상이다. 결과까지 요구하면
모든 중간 턴이 막힌다(제2원칙). 결과는 명령이 에이전트에게 직접 말한다. 게이트가
없애는 것은 **안 돌리고 넘기는 출구** 하나 — `cannot` 과 `pass` 를 가른 것과 같은 모양이다.

*한 번만.* 두 번 막으면 턴이 끝나지 않는다. 비용의 상한은 "소스를 바꾼 턴당 모델
호출 한 번" 이다. 중간 턴이면 에이전트가 그렇다고 말하고 멈추면 된다.

*카운터가 아니라 내용 해시.* 토론에서 나온 반론 — 상태 파일은 수명과 동시성에서
깨진다 — 은 **세는 상태**에 맞다. 여기 남는 것은 한 번 쓰는 기준점과 덧붙이기만
하는 기록이고, 둘 다 트리 해시가 키다. 복사한 인덱스로 해시하므로 실제 인덱스를
건드리지 않고, 커밋 전후로 같은 값이 나온다.

**버린 대안.**

| | 왜 버렸나 |
|---|---|
| 전사(transcript)에서 판정 명령 실행을 찾는다 | 전사 형식은 계약이 아니다. 바뀌면 `cannot` 이 턴마다 난다 |
| 판정 결과까지 통과를 요구 | 중간 턴 전부가 막힌다 |
| 커밋 게이트에 묶는다 | Codex·Gemini 에도 돌지만, 커밋 전 "끝났다" 는 말을 못 잡는다. 말은 턴 끝에 나온다 |
| 차단 메시지에 "판정을 돌려라" 문구만 | 지금과 같다 — 문서 규칙이다 |

**뒤집힐 조건.**

- 한 번 막힌 뒤 에이전트가 **판정 대신 "중간 턴이다" 로 넘기는 일**이 대부분이면
  게이트가 의례가 된 것이다. 막는 조건을 "끝났다" 는 말이 나온 턴으로 좁히는 것
  (`last_assistant_message`)을 다시 잰다 — 단, 문장 판정의 거짓 양성을 먼저 잰다
- 큰 저장소에서 워킹트리 해시가 **체감될 만큼 느리면** 기준을 `git status` 로 줄인다
- 판정 명령이 `echo ok` 로 채워지는 게 관측되면 이 게이트는 형식만 지킨다(D8 과 같다)
