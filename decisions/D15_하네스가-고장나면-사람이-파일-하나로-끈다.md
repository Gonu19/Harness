## D15. 하네스가 고장나면 사람이 파일 하나로 끈다 — 꺼진 것은 크게 보인다 (2026-09-27)

**변경.** `~/.claude/harness-off` 가 있으면 도구 계층 훅(`guard` 를 거치는 다섯 —
`edit-check` · `guard-migrations` · `commit-checklist` · `guard-script-writes` ·
`stop-check`)이 아무것도 검사하지 않고 지나간다. 파일 첫 줄이 이유다.
꺼져 있으면 `gates-report` 가 맨 위에 **★★ 도구 계층이 꺼져 있다** 를 찍고, git 계층이
살아 있어도 **exit 1** 이다. git 계층은 건드리지 않는다(이미 `--no-verify` 가 있다).

**근거.**

*폭발 반경이 하네스 자신이었다.* 도구 계층은 사용자 전역에 걸린다. `guard` 는 하네스의
내부 오류를 제1원칙대로 `cannot`(exit 2)으로 바꾼다 — 그러면 하네스 버그 하나가
**모든 프로젝트의 Write·Edit·Bash 를 막는다.** 에이전트는 스스로 못 푼다(쓸 도구가
전부 막혀 있다). 사람이 할 수 있는 일이 전역 설정 JSON 을 손으로 고치는 것뿐이었다.

*제1원칙을 약하게 하지 않는다.* 내부 오류를 통과로 접으면 비상은 사라지지만 그건
조용한 실패다. 원칙은 그대로 두고, **사람의 명시적 선언**으로만 끈다 — `stack:none`
선언과 같은 모양이다. 선언은 기록이라 읽을 수 있다.

*꺼진 게이트는 없는 것보다 나쁘다.* 그래서 꺼진 상태가 초록으로 보이면 안 된다.
`gates-report` 는 등록 목록을 비워 표가 ★ 를 내게 하고, 끝에서 실패한다. 비상구가
영구 우회로가 되는 것은 **켜는 것을 잊을 때**다 — 실패하는 표가 그걸 잡는다.

*에이전트가 켜고 끄지 않는다.* `~/.claude/**` 편집은 D13 의 ask 규칙에 걸린다.

**버린 대안.**

| | 왜 버렸나 |
|---|---|
| 내부 오류는 통과로 | 제1원칙 위반. 고장이 조용해진다 |
| 환경 변수(`HARNESS_OFF=1`) | 이미 떠 있는 세션에 안 먹는다. 비상은 지금 먹어야 한다 |
| 훅마다 따로 끄기 | 비상 때 어느 훅인지 찾을 여유가 없다. 켤 때는 반대로 하나씩 켜 볼 수 있다 |

**뒤집힐 조건.**

- 스위치가 켜진 채 **며칠씩** 남는 일이 관측되면 `gates-report` 로는 부족하다 —
  SessionStart 에서 매 세션 알리는 것을 잰다(그 출력이 모델에 닿는지 먼저 확인)
- 하네스 버그로 전부 막히는 일이 **한 번도 없으면** 이 스위치는 비용만 있는 것이 아니다 —
  비상구는 안 쓰여도 둔다. 다만 회귀가 계속 이 경로를 본다
