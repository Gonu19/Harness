## D1. 기본 모델은 Sonnet, 승격은 사람이 한다 (2026-09-07)

**변경.** `~/.claude/settings.json` 의 `model` 을 `sonnet` 으로 내렸다.
Opus 로 올리는 것은 사람이 `/model` 로 한다. 승격 신호를 `~/.claude/CLAUDE.md`
에 명시했다 — 미리 아는 신호(스키마·인증 경계·동시성·외부 계약·"어떻게 나눌까")와
겪고 나서 아는 신호(같은 자리 두 번 틀림 · 고쳤더니 딴 데 깨짐 · 원인 후보 3개+ ·
같은 파일 세 번째). 그리고 **내려오는 규칙**도 같이 적었다.

**근거.** 일반 구현·리팩터링은 Sonnet 으로 충분하고 그게 작업의 대부분이다.
자동 라우팅에 맡기지 않은 이유는 **모델이 자기 모델을 못 바꾸기 때문**이다 —
`/model` 은 사람만 친다. 그래서 규칙의 실체는 "모델이 사람에게 올리라고
**말하게** 하는 것" 이고, 목록보다 "작업을 멈추고 말한다" 는 문장이 핵심이다.
말만 하고 진행하면 사람이 읽을 때쯤 이미 잘못된 방향으로 가 있다.

내려오는 규칙을 같이 둔 이유: 없으면 한 번 올라간 세션이 끝까지 Opus 라
기본값을 내린 의미가 사라진다.

훅 설계 같은 경계 판단을 Sonnet 이 못 한다는 뜻은 아니다. 이 저장소의 실제
버그 둘(`process.exit` 이 `finally` 를 건너뜀 · 정규식 `split` 이 따옴표 안
줄바꿈을 자름)은 모델 티어가 아니라 **변조 검증**이 잡았다. 검증 규율이 있으면
Sonnet 으로 안전하고, 없으면 Opus 로도 안 잡힌다.

**전제조건.** statusLine 에 모델명을 띄우는 것이 먼저다(`~/.claude/statusline.mjs`,
Opus 는 반전 표시). 어느 모델로 도는지가 조용하면 **"Opus 인 줄 알고 어려운 걸
맡기는" 세션**이 생기고, 그건 꺼진 게이트와 같은 실패 형태다.

**뒤집힐 조건.**

- 한 달 안에 "Opus 로 올려라" 는 제안을 **한 번도 못 받았는데** 그 사이
  마이그레이션·인증 작업을 했다 → 규칙이 죽은 것이다. 이때 고칠 곳은 트리거
  목록이 아니라 "멈추고 말한다" 는 문장이다
- 반대로 제안이 너무 잦아 무시하게 됐다 → 미리 아는 신호 쪽을 줄인다
- Claude Code 가 세션 중 모델 전환을 모델에게 허용하면 이 결정의 전제가 바뀐다
