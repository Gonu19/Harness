## D6. 파일 내용은 스크립트가 아니라 도구로 쓴다 — 게이트로 막는다 (2026-09-22)

**변경.** 파일 내용은 Write/Edit 도구로만 쓴다. 스크립트(python·heredoc)는
읽기·측정·이동에만. 이 규칙을 **게이트**로 올렸다 — `guard-script-writes`
(PreToolUse · Bash)가 python 이 파일에 쓰는 명령을 막는다.

**근거 — 두 실패가 모두 조용하다.**

| | 무슨 일이 일어나나 |
|---|---|
| ① 이스케이프 3중 해석 | 셸 → python 문자열 → 대상 언어. `\n` 이 실제 줄바꿈이 되어 대상 파일이 **문법 오류로 죽었다**(`gates-report.mjs`) |
| ② 못 찾아도 성공 | `str.replace(old, new)` 는 `old` 가 없으면 원본을 돌려준다. 편집이 안 됐는데 됐다고 믿었고, 실행해서야 `ledger is not defined` 로 알았다 |

②가 핵심이다. 하네스 말로 **`cannot` 을 `pass` 로 접는 도구**다. Edit 도구는
못 찾으면 거부하고, 마지막으로 읽은 뒤 파일이 바뀌었으면 거부한다. 그러니
스크립트로 파일을 고치는 것은 **하네스가 코드에서 없앤 실패를 에이전트가
제 손으로 다시 들여오는 것**이다. 이 규칙은 스타일이 아니라 제1원칙의 조각이다.

**왜 문서가 아니라 게이트인가.** 이 규칙은 `AGENTS.md` 에 적혀 있었고 지뢰표에도
있었다. 그런데 **한 세션에 세 번 어겼다.** 이 저장소의 규칙 — *"같은 도구
실패가 두 번째면 관측이 아니라 결정이다"* — 을 한참 넘었다. 문서에 적힌
금지는 스스로 집행하지 않는다는 것이 세 번 증명됐다.

**좁게 막는다.** 넓게 막으면 거짓 차단으로 게이트가 꺼진다.

| | 판정 |
|---|---|
| python 실행 + `open(…, 'w'\|'a'\|'x')` · `mode='w'` · `.write_text(` · `.write_bytes(` | **막는다** |
| python 읽기·측정 | 통과 |
| `git commit -F - <<'EOF'` — 메시지가 `open(p, 'w')` 를 **논해도** | **통과** — 실행 파일이 `git` 이다 |
| `node -e` · `echo > 파일` | 통과 (범위 밖) |

실행 파일은 **heredoc 본문을 뺀 조각의 첫 토큰**으로 가른다(`commandHeads`).
이게 없으면 이 결정의 커밋 메시지부터 막힌다. 이번 세션의 모든 커밋이
heredoc 이었으므로 이 통과 사례가 막힘 사례보다 중요하다.

**만들면서 잡힌 거짓 양성.** 처음 정규식은 `open('a').read()` 의 `'a'` 를 모드로
읽고 **읽기를 막았다.** 모드는 두 번째 인자라 쉼표 뒤로 좁혔다. 회귀에 그 모양을
남겼다.

**막는 상대가 에이전트라는 점.** 거짓 차단이 나도 에이전트는 Edit 로 바꿔 쓰면
끝이라 사람 게이트보다 비용이 싸다. **단 대체 수단이 없는 것(커밋)을 막으면
비용이 크다** — 그래서 통과 목록이 설계의 중심이다.

**범위 밖으로 둔 것.** `sed -i` · `perl -pi` 도 ②와 같은 실패를 한다. 하지만
흔하게 쓰이고, 실제로 어긴 것은 python 이었다. 거짓 차단을 재지 않고 넓히지 않는다.

**뒤집힐 조건.**

- 이 게이트가 **정당한 작업을 막는 일**이 관측되면(특히 커밋·측정) 표지를
  더 좁힌다. 좁힐 수 없으면 알림으로 내린다
- `sed -i` 로 **같은 실패(못 찾아 조용히 안 바뀜)**가 실제로 일어나면 그때
  범위를 넓힌다 — 이 결정과 같은 기준(두 번째면 결정)
- 에이전트 도구가 스크립트 쓰기에도 "못 찾으면 실패" 를 보장하게 되면
  이 게이트의 근거 ②가 사라진다

**관련.** [[D2_서브에이전트는-성격으로-티어를-가른다]] — 같은 원리: 판정 실패를
표현할 수단이 없는 곳에서는 사람이 도구 선택으로 막는다.
