## D20. 사이클은 선언하지 않고 사실에서 다음 활동을 계산한다 — 세션 시작에 알린다 (2026-09-28)

**변경.**

- `scripts/next.mjs` — 지금 할 활동 하나(기획 · 구현 · QA · 문서화 · 회고)와 이유,
  할 일을 말한다. **막지 않는다.** 판단은 `core/cycle.mjs` 의 `nextActivity`
- 재료는 사실뿐이다 — `STATUS.md` 「이번 반복」 · PRD 기능 표 · 판정 기록(`done.jsonl`)
  · 지금 워킹트리 해시 · `git status`
- 「이번 반복」 에 선택 줄 `- 기능: F1, F2` — 이번 반복의 범위. 없으면 전부
- SessionStart 훅(`session-baseline`)이 하네스를 쓰는 저장소에서 세 줄 요약을 stdout 으로
  낸다 — 에이전트 컨텍스트에 **세션마다 먼저** 들어간다
- `gates-report` 가 「다음」 한 줄을 보여 준다. 반복·OPEN 읽기는 `core/cycle.mjs` 로 옮겨
  둘이 같은 읽기를 쓴다
- 이식 템플릿: AGENTS 「세션 시작 시」 3번 · `cycle.md` 에 두 번째 반복부터의 기획 절차 ·
  두 스킬이 「기능」 줄을 쓴다

판단의 순서 — 앞에서 걸리면 거기가 답이다:

| 사실 | 활동 |
|---|---|
| 반복이 없다 · 목표·시작일을 못 읽었다 | 기획 |
| PRD 가 없다 · PRD·C4 에 채울 칸 | 기획 |
| 범위의 기능이 PRD 에 없다 · 판정 명령이 없다 | 기획 |
| 지금 코드에서 판정이 **실패** | 구현 (고친다) |
| 판정이 한 번도 안 돌았다 | 구현 (만든다) |
| 판정 뒤로 코드가 바뀌었다 | QA |
| 전부 지금 코드에서 통과 · 커밋 안 된 변경 | 문서화 |
| 전부 통과 · 깨끗하다 | 회고 |

**근거.**

*S4 의 답은 문서 규칙이 아니라 장치여야 했다.* D12 는 "한 번에 한 활동" 을 규칙으로
적었다. 문서 규칙은 스스로 집행되지 않는다(D6). 에이전트가 역할을 섞는 이유 중 하나는
**지금 무엇을 할 차례인지 모르기 때문**이고, 그걸 매 세션 첫 줄에서 알려 주면 섞을
이유가 줄어든다.

*선언하지 않는다.* `phase` 를 되살리면 D5 로 돌아간다 — 선언은 낡고, 애자일에서 기획은
매 반복 온다. 여기서 활동은 **적힌 값이 아니라 계산된 값**이라 낡을 수 없다. 코드가 바뀌면
QA 로, 판정이 통과하면 문서화로 저절로 넘어간다. 「기능」 줄은 선언이지만 반복의 범위이고,
반복 경계(회고)에서만 바뀐다 — D5 가 허용한 가벼운 기록과 같은 급이다.

*실패가 새 기능보다 먼저다.* 깨진 것을 두고 다음 것을 짓지 않는다.

*막지 않는다.* 활동의 판단이 틀릴 수 있다(판정 명령이 기능을 다 못 잴 때). 막으면
거짓 차단이고, 알리면 에이전트와 사람이 판단한다. 막는 일은 이미 게이트가 한다 —
QA 를 건너뛴 것은 Stop(D11)이 잡는다.

**버린 대안.**

| | 왜 버렸나 |
|---|---|
| `phase` 선언을 되살린다 | D5 — 낡는다 |
| 활동별 서브에이전트(기획자·구현자·QA) | D12 — 맥락을 다시 읽고 잃는다 |
| 역할 밖 파일 편집을 막는다 | 거짓 차단. 작은 수정은 여러 활동에 걸친다 |
| 전사(transcript)로 활동을 추정 | 전사 형식은 계약이 아니다 |

**뒤집힐 조건.**

- SessionStart 의 stdout 이 **실제 세션 컨텍스트에 안 들어가면** 이 결정의 절반이 없다 —
  발화 확인 전이다(STATUS). 안 들어가면 AGENTS 의 3번(직접 묻기)만 남는다
- 안내를 받고도 역할이 섞이는 일(구현 중 PRD 판정 칸 수정)이 관측되면 그 좁은 경우만
  알림 게이트로 잰다(D12 의 뒤집힐 조건과 같다)
- 판정 명령이 기능을 다 못 재서 「회고」 가 너무 일찍 나오면 — 판정 명령이 약한 것이다.
  `next` 가 아니라 PRD 를 고친다
