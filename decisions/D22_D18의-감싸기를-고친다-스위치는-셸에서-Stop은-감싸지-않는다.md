## D22. D18 의 감싸기를 고친다 — 스위치는 셸에서도 보고, Stop 은 감싸지 않는다 (2026-10-01)

**변경.** D18 이 넣은 훅 명령 줄 감싸기(`node … || exit 2`)를 둘 고친다.

- **끄는 스위치(D15)를 명령 줄에서 먼저 본다.**
  bash `[ -e "${HARNESS_OFF_FILE:-$HOME/.claude/harness-off}" ] || node … || exit 2`,
  PowerShell 은 `Test-Path` 로 같은 일을 한다
- **Stop 훅은 감싸지 않는다.**
- `gates-report` 가 옛 설치의 두 모양을 ★ 로 말한다 — 감쌌는데 스위치를 셸에서 안 보는 훅,
  감싸인 Stop 훅. `install.mjs` 를 다시 돌리면 고쳐진다

D18 의 감싸기 자체는 그대로다 — node 가 뜨지 못한 것(127)이 조용히 통과하면 안 된다.

**근거.**

*감싸기가 비상구를 막았다.* 감싸면 node 가 없을 때 모든 프로젝트의 Write·Edit·Bash·
PowerShell 이 막힌다. 그때 사람이 쓸 비상구가 D15 의 스위치인데, 스위치 확인이 node 안
(`hook-io.guard`)에만 있었다. **node 가 없어 막힌 바로 그 경우에 스위치가 듣지 않는다.**
재현했다 — 스위치를 켠 채 node 없이 감싼 줄을 돌리면 exit 2.

*Stop 은 2 가 나가면 턴이 끝나지 않는다.* "한 번만 막는다"(`stop_hook_active`, D11)는 판단이
node 안에 있다. node 가 없으면 그 판단도 없어서 매번 2 가 나간다. 공식 문서에는 Stop 훅이
계속 막을 때의 반복 방지 장치가 적혀 있지 않다. 조용히 지나가는 쪽이 낫다 — 2 가 아닌
종료는 전사에 "hook error" 로 보이므로 완전히 조용하지는 않다.

*제1원칙과 부딪히지 않는다.* 스위치는 사람의 명시적 선언이고(D15), 꺼져 있으면
`gates-report` 가 실패한다. Stop 을 풀어 주는 것은 "판정 실패는 통과가 아니다" 의 예외지만,
막았을 때의 결과가 **끝나지 않는 턴**이라 거짓 차단보다 나쁘다(제2원칙).

**버린 대안.**

| | 왜 버렸나 |
|---|---|
| 감싸기를 되돌린다 | D18 의 구멍(node 없으면 전부 조용히 통과)이 다시 열린다 |
| Stop 줄에서 `stop_hook_active` 를 셸로 읽는다(grep) | 입력 JSON 을 셸 정규식으로 읽는 것은 깨지기 쉽고, 깨지면 조용하다 |
| 스위치를 환경변수로 | D15 — 이미 떠 있는 세션에 안 먹는다 |

**뒤집힐 조건.**

- Claude Code 가 Stop 훅의 연속 차단에 **상한**을 두면 Stop 도 감쌀 수 있다
- node 가 없는 채 Stop 이 지나가 **판정 없이 끝난 턴**이 관측되면 — 감싸는 대신 세션 시작에
  node 를 확인해 알리는 쪽을 잰다
