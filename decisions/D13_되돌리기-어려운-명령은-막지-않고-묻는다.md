## D13. 되돌리기 어려운 명령은 막지 않고 묻는다 — 권한 ask 를 이식한다 (2026-09-27)

**변경.** 이식 템플릿이 프로젝트 공용 `.claude/settings.json` 을 놓는다. 내용은
`permissions.ask` 뿐이다 — `git push` · `git reset --hard` · `git clean` ·
`git branch -D` · `git config --global` · `rm -rf` · `~/.gitconfig` 와 `~/.claude/**` 편집.
`gates-report` 는 묻는 규칙이 몇 줄인지 **보여 주고, 막지 않는다.** 이 저장소에도 같은 파일을 둔다.

**근거.**

*실행 환경의 안전이 비어 있었다.* 하네스의 게이트는 "판정" 을 지키지 저장소 밖으로
나가는 행동은 몰랐다. 전역 설정 수정 · 강제 푸시 · 워킹트리 날리기는 게이트가 볼
자리가 없다.

*`deny` 가 아니라 `ask`.* 토론의 반론이 맞았다 — 꼬인 저장소를 푸려면 `reset --hard`
가 필요할 때가 있다. 막으면 복구 경로까지 막힌다. 묻기는 **사람을 루프에 넣는 스위치**
고, 사람이 "예" 하면 복구는 그대로 된다.

*훅이 아니라 권한 규칙.* ask 는 Claude Code 가 직접 집행한다 — 폴더 신뢰 전에도,
`cd x && git push` 같은 하위 명령에도, PreToolUse 훅이 allow 를 돌려도 묻는다(공식 문서).
같은 일을 훅으로 하면 명령 파싱을 우리가 다시 짜야 하고, 틀리면 조용하다.

*`"//"` 주석 키를 넣지 않았다.* 설정 검증이 모르는 키를 어떻게 다루는지 확인하지 못했다.
권한 파일이 통째로 무시되면 그건 조용한 실패다. 설명은 여기 둔다.

*막지 않는다.* 어떤 명령을 물을지는 프로젝트의 판단이다. 없다고 `gates-report` 가
실패하면 거짓 차단이다(제2원칙). 다만 **없는 것이 조용하면 안 되므로** 말한다.

**버린 대안.**

| | 왜 버렸나 |
|---|---|
| `deny` | 복구 경로를 막는다 |
| PreToolUse 훅으로 위험 명령 차단 | 권한 규칙이 이미 하위 명령까지 집행한다. 두 벌이다 |
| 전역(`~/.claude/settings.json`)에 건다 | 프로젝트마다 판단이 다르고, 팀원에게 안 간다. 공용 파일은 커밋되어 같이 간다 |

**뒤집힐 조건.**

- 묻기가 너무 잦아 사람이 **읽지 않고 "예" 를 누르게** 되면 규칙이 의례가 된 것이다.
  줄을 줄인다 — 늘리지 않는다
- 에이전트가 ask 를 피해 다른 명령으로 같은 일을 하는 것(`git push` 대신 스크립트)이
  관측되면 그 경로만 좁게 더한다
- 설정의 `"//"` 키가 안전하다는 것이 확인되면 이유를 파일에 되돌린다

**관련.** [[D11_완료-판정은-Stop-훅이-돌았는지만-묻는다]] — 막는 것은 한 번, 나머지는 사람.
