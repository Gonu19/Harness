## D9. 도구가 말할 수 있는 것은 문서에 적지 않는다 (2026-09-26)

**변경.** 문서에 **관측값**(도구가 매번 다시 세는 값 — 테스트 건수·결정 개수·
파일 크기)을 적지 않는다. 값 대신 **부르는 법**을 적는다.

```
- 되는 것 — 131건 회귀로 검증됨
+ 되는 것 — 변조 회귀로 검증됨 (`verify` 가 센다)
```

가르는 한 줄은 **"문서를 안 고쳐도 이 값이 틀려질 수 있나"** 다. 규칙 본문은
`.claude/rules/writing-docs.md`, 이식본은 `template/.claude/rules/decisions.md.tpl`.

**게이트는 만들지 않는다.** 아래 근거 참조.

**근거.**

*네 번 낡았고, 두 번은 틀린 채로 커밋됐다.*

| 어디 | 무슨 일 |
|---|---|
| `STATUS.md` | 회귀 건수를 손으로 **아홉 번** 고쳤다 (60→…→131) |
| `bbffa2e`·`affe6b9` | 같은 커밋 안에서 STATUS 는 `95`, 커밋 메시지는 `97`·`100` |
| `README.md` | **한 파일 안에** `43건`(39행)·`89건`(49행). 실제는 131 |
| `OPEN.md` | "결정이 10개를 넘는가 (지금 4)" — 실제 6. **트리거 판단의 근거였다** |

*실패가 조용하다.* `43건` 은 `131건` 과 똑같이 생겼다. diff 도 오류도 없다.
게이트가 없애려는 바로 그 모양 — **`cannot` 이어야 할 것이 `pass` 로 나간다.**

*고칠 기회가 구조적으로 없다.* 낡았는지 판정하려면 **참값을 알아야** 하는데,
참값을 알 수 있으면 **복사본이 애초에 필요 없다.** 검사 가능한 값은 적을 이유가
없고, 적어야만 하는 값은 검사할 수 없다.

*`131` 은 상수도 아니었다.* `verify` 는 javac·typescript 가 없으면 그 경로를
건너뛴다. 다른 기계에서는 다른 수가 나온다 — "그때는 맞았다" 조차 아니다.

*원칙은 이미 세 곳에 흩어져 있었다.* `instructions-log.mjs` 주석("하네스가
직접 말하게 한다"), `template/decisions/OPEN.md.tpl` 주석("숫자를 적지 마라"),
`README` 주석. **규칙으로는 어디에도 없어서** 세 곳 다 자기 파일 밖을 못 막았다.

**버린 대안.**

| | 왜 버렸나 |
|---|---|
| 숫자+단위 정규식 게이트 | 문서의 숫자는 **대부분 결정값**(3KB·10개·400바이트)이다. 거짓 차단이 통과보다 많다 — 제2원칙 |
| 숫자 옆에 측정 날짜 병기 | 낡음을 **보이게만** 한다. 아무도 안 고치는 건 같고, 날짜도 같이 낡는다 |
| 스크립트가 문서의 숫자를 치환 | `D6` 위반(파일 내용은 도구로). 기계가 쓰는 문서는 사람이 안 읽는다 |

**만들면서 드러난 것.**

- 전수 검사했더니 위반은 **`STATUS.md` 한 줄뿐**이었다. 나머지 숫자는 전부
  결정값이거나 날짜 박힌 과거 측정이다 — 한 줄 테스트가 실제로 갈라낸다
- `RUNBOOK.md` 는 처음부터 지키고 있었다("스크립트가 스스로 찍으니 옮겨 적지
  않는다"). **규칙을 문장으로 쥔 파일만 안 낡았다**

**뒤집힐 조건.**

- 규칙을 넣고도 관측값이 또 적히면 문서 규칙으로는 부족한 것이다(`D6` 과 같은
  증상). 그때 게이트를 다시 잰다 — 단 **거짓 차단을 못 줄이면 만들지 않는다**
- 도구가 못 세는데 꼭 필요한 값이 생기면 문서에 적을 게 아니라 **도구를 고친다**

**관련.** [[D6_파일-내용은-스크립트가-아니라-도구로-쓴다]] — 규칙이 문서에만
있으면 안 지켜진다는 같은 증상. [[D8_기능의-완성-기준은-실행-가능한-명령이다]]
— 말 대신 명령이 판정한다는 같은 형태.
