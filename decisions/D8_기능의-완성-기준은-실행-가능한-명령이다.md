## D8. 기능의 완성 기준은 실행 가능한 명령이다 (2026-09-23)

**변경.** `PRD.md` 「핵심 기능」을 표로 바꾸고 **「완료 판정」 열**을 둔다. 값은
**실행 가능한 명령 하나**(백틱). 에이전트 규칙: **기능이 끝났다고 말하기 전에
그 명령을 돌린다. 안 돌렸으면 끝난 게 아니다.** `gates-report` 는 판정 명령이
없는 기능을 센다 — 막지 않는다.

이 저장소는 `verify --only <검사>` 로 기능마다 판정한다.

**근거.**

*완성 기준이 네 층 중 가장 중요한 층에 없었다.*

| 층 | 기준 | 판정 |
|---|---|---|
| 커밋 | 게이트 | 기계 |
| 이식 | `gates-report` exit 0 | 기계 |
| 반복 | 「이번 반복」 목표 한 줄 | 사람 |
| **기능** | **없었다** | — |

애자일에서 "끝났다" 의 기본 단위는 기능(스토리)이다. 참조 프레임워크의 "AC 는
실행 가능한 커맨드" 를 첫날 가져올 만하다고 짚고 **가져오지 않았다.**

*QA 의 빈칸이기도 했다.* 테스트 미동반은 알리기만 한다(거짓 차단 방지). 그러면
"이 기능이 끝나려면 무엇이 통과해야 하나" 가 어디에도 없다. 판정 명령이 곧 그
기능의 테스트다.

*명령이어야 하는 이유.* "로그인이 동작한다" 는 에이전트가 **말로 통과시킬 수
있다.** 명령은 exit 코드가 말한다 — 제1원칙(판정은 사실로)의 기능판이다.

**버린 대안.**

| | 왜 버렸나 |
|---|---|
| 참조식 step 파일마다 AC | 반복마다 파일이 는다. `D5` 에서 구조적 반복을 버린 것과 같은 이유 |
| 반복 목표에만 판정 | 반복은 여러 기능을 묶는다. 기능 하나가 끝났는지는 여전히 모른다 |
| 판정 없는 기능을 막기 | 아직 만들기 전인 기능이 목록에 있는 건 정상이다. 거짓 차단 |

**만들면서 드러난 것.**

- **기능별로 판정을 쪼개자 결함이 잡혔다.** 규칙 한 줄을 넣은 템플릿
  `AGENTS.md` 가 **이식되자마자 자기 예산을 81바이트 넘었다** — 새 프로젝트의
  첫 커밋을 하네스 자기 템플릿이 막는다. F2(이식) 판정을 따로 돌리다 걸렸다.
  크기를 재야 할 대상은 템플릿 파일이 아니라 **이식된 결과물**이고, e2e 가 그걸 한다
- **`--only` 오타는 "0건 통과" 가 된다.** 완료 판정이 아무것도 안 재고 통과를
  말하는 것이다. 모르는 이름·0건 실행은 exit 2 로 막았다

**뒤집힐 조건.**

- 판정 명령이 **돌려지지 않은 채** "끝났다" 가 반복되면 규칙이 문서에만 있는
  것이다(`D6` 과 같은 증상). 그때는 커밋 게이트에 묶는 것 — 예를 들어 기능 ID 를
  커밋에 적으면 그 판정을 돌리게 — 을 다시 잰다
- 명령이 **형식만 채워진 것**(`echo ok`)이 관측되면 백틱 판정이 무의미해진 것이다
