# harness-init — greenfield 온보딩

**빈 프로젝트에 하네스를 놓고, 그 세션에서 문서를 채운다.**

코드가 이미 있는 저장소를 분석하는 것이 아니다. 그건 `codebase-onboarding` 이다.
여기는 **아직 아무것도 없는** 상태에서 시작한다.

## 역할 경계 — 이걸 어기면 온보딩이 검증 불가가 된다

| | 누가 | 검증 |
|---|---|---|
| **무엇이 있어야 하는가** | `apply-template.mjs` | 목록이 코드에 있다. 회귀 있음 |
| **무엇을 적어야 하는가** | 이 스킬(에이전트) | 없다 — 그래서 **산출물에 판정을 건다** |

**파일을 스킬이 놓지 마라.** 빠뜨려도 조용하다. 반드시 스크립트를 부른다.

---

## 절차

### 1. 놓는다

```bash
node <하네스>/scripts/apply-template.mjs <프로젝트> [--with old,reference]
```

`--with` 는 **해당할 때만**. `old/` 는 이전 기획물이 있을 때, `Reference/` 는
사용자가 외부 재료를 올릴 자리가 필요할 때. 빈 인덱스 표를 만들어 두면
**"아직 안 봤다" 와 "볼 게 없다" 가 구별되지 않는다.**

거부(exit 1)가 나오면 **멈추고 사람에게 알린다.** 합치는 것은 사람 몫이다.

### 2. 재료를 읽는다 — 인덱스 먼저

`old/README.md` 와 `Reference/README.md` 의 **표만** 먼저 읽는다.
본문은 그 표를 보고 **필요한 것만** 연다. 통째로 읽으면 컨텍스트를 태우고,
태운 만큼 정작 작업할 자리가 줄어든다.

이미지·PDF 는 특히 비싸다. **열기 전에 "이걸 왜 여는지" 가 있어야 한다.**

`old/` 를 다 읽었으면 인덱스 표의 「상태」를 갱신한다 —
`안 봄` / `옮김 → <어디로>` / `버림(이유)`. **"안 옮겼다" 와 "못 봤다" 는 다르다.**

### 3. 사람에게 묻는다 — 셋만

1. **무엇을 만드나** (한두 문장)
2. **스택** — 언어·프레임워크·빌드 도구. 모르면 "아직 없음" 도 답이다
3. **첫 마일스톤** — 무엇이 되면 1단계가 끝인가

넷째부터는 묻지 말고 **초안을 써서 보여 준 뒤 고친다.** 빈 칸을 연속으로
물으면 사람이 지치고, **지친 답이 그대로 문서가 된다.**

### 4. 채운다 — 채우는 칸과 채우면 안 되는 칸

| 파일 | 채운다 | **채우지 않는다** |
|---|---|---|
| `AGENTS.md` | 프로젝트 이름 · 스택 · CRITICAL 규칙 | 하네스 공통 규칙(이미 있다) |
| `RUNBOOK.md` | 빌드·테스트·앱 실행 명령 | **돌려 보지 않은 명령** |
| `STATUS.md` | 「진행 중」 · 「막힌 것」 | **「도는 것」** |
| `decisions/` | 이 세션에서 정한 것 | 아직 안 정한 것 |

**`STATUS.md` 의 「도는 것」은 비운다.** 새 프로젝트에는 도는 것이 없다.
계획을 여기 적으면 그 문서는 낡은 것보다 나쁘다 — **처음부터 틀렸는데 사실로
읽힌다.** 정직한 첫날 내용은 `아직 아무것도 안 돈다. 다음 검증은 <무엇>.` 한 줄이다.

**`RUNBOOK.md` 에 적는 명령은 한 번씩 실제로 돌린다.** 안 돌면 적지 않는다.
`RUNBOOK` 의 약속이 "재발명하지 않는다" 인데, **안 도는 명령이 적혀 있으면
다음 세션이 그걸 믿고 시간을 태운다.** 낡은 지도보다 나쁜 것이 틀린 지도다.
아직 빌드가 없으면 그 칸을 비우고 「막힌 것」에 그렇게 적는다.

### 5. 스택을 확정하고 게이트를 본다

```bash
node <하네스>/scripts/gates-report.mjs <프로젝트>
```

- `★ 이 스택용 구현이 없다` → 하네스에 게이트를 붙일지 사람에게 묻는다.
  **짚어 놓고 방치하면 표만 늘어난다**
- `★ 스택을 알아보지 못했다` → 빌드가 없는 프로젝트면
  `.claude/harness-gates.json` 에 `{"stack":"none"}` 을 **선언**한다.
  선언은 기록이라 나중에 읽을 수 있다. 기본값의 침묵과 다르다

### 6. 완료 판정 — 넷 다 기계로

```bash
node <하네스>/scripts/gates-report.mjs <프로젝트>   # exit 0
node <하네스>/scripts/budget.mjs       <프로젝트>   # exit 0
```

그리고 사람이 볼 것 둘:

- `RUNBOOK.md` 의 명령이 **전부 실제로 돌았다**
- `STATUS.md` 의 「도는 것」이 비어 있거나 **진짜 되는 것만** 있다

마지막으로 첫 커밋을 만든다. **이 커밋이 곧 시험이다** — 문서를 부풀렸으면
`commit-msg` 의 예산 검사에서 막힌다. 막히면 줄이지 말고 **내려보낸다**
(`.claude/rules/` 의 `paths:`).

> `git add` 를 `git commit` 과 **한 명령으로 묶지 마라.** PreToolUse 훅은
> 명령 전체를 막으므로 `add` 가 안 돌고, 게이트가 직전 인덱스를 잰다.

## 템플릿 밖의 파일을 만들고 싶을 때

**먼저 사람의 승인을 받는다.** 그리고 승인을 구할 때 **왜 템플릿으로 안 되는지**
한 줄로 말한다. "있으면 편해서" 는 이유가 아니다.

> **같은 이유가 두 번째면 템플릿이 틀린 것이다.**
> 그때는 파일을 하나 더 만들지 말고 **하네스에 되먹인다** —
> `<하네스>/template/` 에 넣고 `apply-template.mjs` 의 `FILES` 에 한 줄.
> 그러면 다음 프로젝트부터는 아무도 같은 판단을 다시 하지 않는다.

이 저장소의 *"같은 도구 실패가 두 번째면 결정이다"* 와 같은 구조다.

## `old/` 와 `Reference/` 는 다르다 — 한 규약으로 묶지 마라

| | `old/` | `Reference/` |
|---|---|---|
| 무엇 | 이 프로젝트의 **과거 기획** | **외부** 재료 |
| 수명 | 옮기고 **지운다** | 계속 둔다 |
| git | 들어간다 (옮긴 흔적이 diff 로 남아야) | **제외** — 인덱스만 커밋 |
| 위험 | 두 벌의 진실 | 남의 결론을 규칙으로 물려받음 |

`Reference/` 를 보고 무언가 정했으면 `decisions/` 에 **자기 말로** 근거를 적는다.
"Reference 의 X 가 그렇게 해서" 는 근거가 아니다 — 남의 프로젝트는 남의 제약
아래에서 그 답에 도달했고, **그 제약이 여기에도 있는지는 별개의 판단**이다.

## 하지 않는 것

- **파일 놓기** — 스크립트가 한다
- **훅 등록** — `~/.claude/settings.json` 은 사용자 전역이라 사람이 한 번 한다
- **`git push`** — 원격은 사람이 한다
- **`--force` 로 밀어붙이기** — 거부가 나오면 멈추고 알린다
