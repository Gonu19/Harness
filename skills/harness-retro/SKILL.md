# harness-retro — 반복을 닫는다

**회고는 이미 하고 있다. 빠진 것은 그게 남을 자리다.**

반복이 끝날 때마다 "무엇을 했고, 무엇이 틀렸고, 무엇이 새로 궁금해졌나" 를
말한다. 그런데 그 말이 채팅에만 있으면 `/clear` 에 사라진다. 남는 건 누가
그때그때 챙긴 것뿐이고, **챙길지 말지가 운이다.** 이 스킬은 그 운을 없앤다.

## 원칙 — 회고는 새 파일을 만들지 않는다

회고의 **산출물**은 이미 있는 네 곳으로 흩어진다. 회고의 **서술**은 커밋
메시지에 남는다. 그래서 파일도 예산도 늘지 않는다.

| 무엇 | 어디로 | 왜 거기 |
|---|---|---|
| 밟은 지뢰 | `RUNBOOK.md` 지뢰표 | 다음 세션이 같은 시간을 안 쓰게 |
| 새로 생긴 의문 | `decisions/OPEN.md` | **루프가 닫히는 자리** — 다음 반복의 기획으로 |
| 정한 것 | `decisions/D<n>` | 대안·근거·뒤집힐 조건이 있을 때만 |
| 되는 것 | `STATUS.md` 「도는 것」 | **실제로 도는 것만** |
| 무엇을 배웠나 (서술) | **회고 커밋 메시지** | 예산을 안 먹고, `git log --grep 회고:` 로 찾는다 |

②가 핵심이다. 네 활동이 원이 되려면 **문서화에서 기획으로 돌아가는 화살표**가
있어야 한다. 구현·QA 중에 생긴 의문이 `OPEN.md` 로 들어가는 것이 그 화살표다.

---

## 절차

### 0. 이번 반복을 확인한다

`STATUS.md` 의 「이번 반복」 — 시작일과 목표를 읽는다. **목표가 됐나?**
됐으면 회고, 안 됐으면 **왜 안 됐는지가 회고의 첫 줄**이다.
목표를 슬쩍 줄여서 "됐다" 로 만들지 마라 — 그건 회고가 아니라 합리화다.

### 1. 이번 반복에서 일어난 일을 모은다

채팅·커밋 로그·`STATUS.md` 변경을 훑는다. 특히 찾는 것:

- **실패한 것** — 명령이 안 돌았다 · 게이트가 막았다 · 가정이 틀렸다
- **돌아간 것** — 한 번에 안 되고 두세 번 걸린 것
- **미룬 것** — "나중에" 라고 말한 것

```bash
git log --oneline --grep '^회고:' -1            # 지난 회고 커밋
git log --oneline <지난 회고 커밋>..HEAD
git log --oneline --since <「이번 반복」 시작일>   # 첫 회고면 지난 회고가 없다
```

**채팅도 훑는다.** 커밋에는 성공한 것만 남는다 — 게이트에 막혔다가 고친 것,
세 번 만에 된 것은 커밋 로그에 안 보인다. 회고할 값이 가장 큰 것들이다.

### 2. 넷으로 가른다 — 사람이 확정한다

위 표의 네 곳에 **초안을 보여 주고 사람이 고른다.** 자동으로 쓰지 않는다 —
자동으로 쓰면 검증 안 된 것이 쌓이고, 그러면 아무도 안 연다.

가를 때 규칙 둘:

- **관측이냐 결정이냐.** 선택지가 없으면 관측(지뢰표 한 줄), 대안·근거·
  뒤집힐 조건이 있으면 결정. **같은 도구 실패가 두 번째면 결정이다**
- **새 의문은 반드시 `OPEN.md` 로.** "나중에 보자" 로 채팅에 남긴 것은
  다음 반복에서 사라진다. 이게 이 스킬이 막으려는 것의 대부분이다

### 3. `OPEN.md` 를 정리한다

- 이번 반복에 **닫힌 것**은 `D<n>` 으로 올리고 표에서 **지운다**
- **나이를 본다.** `gates-report` 의 기획 지표가 「고르는 중」의 나이만 센다.
  반복을 두세 번 넘긴 질문은 — 지금 물을 때가 아니거나, 닫기를 피하고 있거나
  둘 중 하나다. 어느 쪽인지 사람에게 묻는다. **지금 물을 때가 아니면 「조건
  대기」로 옮긴다** — 원래 늙어야 하는 질문이 나이 지표를 차지하면, 닫기를
  피하는 질문이 생겨도 그 숫자에 묻혀 안 보인다
- **적힌 사실이 낡았나 본다.** 「무엇을 알아야 닫히나」에 숫자를 적었으면
  (예: "결정 N개") 지금도 맞는지 확인한다

### 4. 다음 반복을 연다

`STATUS.md` 의 「이번 반복」을 **갈아 쓴다** — 새 시작일, 새 목표 한 줄.
지난 반복을 여기 쌓지 않는다. 그건 커밋 메시지에 있다.

목표는 **끝났을 때 판정할 수 있는 말**로 쓴다.
"인증 개선" 은 판정이 안 된다. "로그인이 외부 인증으로 된다" 는 된다.

### 5. 판정하고 커밋한다

```bash
node <하네스>/scripts/budget.mjs .        # 문서가 한도 안인가
node <하네스>/scripts/gates-report.mjs .  # 네 활동이 산다
```

커밋 메시지 첫 줄은 `회고: <반복 목표 요약>`. 본문에 **무엇을 배웠나**를 적는다.
게이트가 이 커밋을 검사한다 — `decisions/` 가 바뀌었으면 `OPEN.md` 도 같이
와야 하고, 문서가 한도를 넘으면 막힌다. **회고가 문서를 부풀리면 거기서 걸린다.**

> `git add` 와 `git commit` 을 한 명령으로 묶지 마라. PreToolUse 훅은 명령
> 전체를 막으므로 `add` 가 안 돌고, 게이트가 직전 인덱스를 잰다.

---

## 하지 않는 것

- **회고 파일을 따로 만들지 않는다.** 산출물은 네 곳으로, 서술은 커밋으로
- **목표를 줄여서 달성으로 만들지 않는다**
- **다음 반복 목표를 여럿 적지 않는다.** 한 줄이다. 여럿이면 반복이 아니라 백로그다
- 사람 확정 없이 `OPEN.md`·`decisions/` 에 쓰지 않는다
