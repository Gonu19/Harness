# 새 프로젝트에 붙이는 순서

> **각 단계에 「완료 판정」이 있다.** 없으면 단계가 아니라 희망이다.
> 특히 조용히 아무 일도 안 하는 실패는 판정 없이는 몇 달 뒤에도 안 드러난다.

## 세 줄 요약

```bash
node <하네스>/scripts/apply-template.mjs <프로젝트> [--with old,reference]
node <하네스>/adapters/git/install.mjs   <프로젝트>
node <하네스>/scripts/gates-report.mjs   <프로젝트>   # ← exit 0 이어야 끝이다
```

Claude Code 훅은 **사용자 전역에 한 번만** 건다(아래 0단계). 프로젝트마다가 아니다.

> **빈 프로젝트를 시작하는 것이면 `/harness-init` 스킬을 써라.** 위 셋을
> 부르고, 그 세션에서 문서를 채우고, 완료 판정까지 본다. 아래는 그 스킬이
> 하는 일의 절차판이자 손으로 할 때의 순서다.

---

## 0. 한 번만 하는 것 — 사용자 전역

프로젝트마다 다시 하지 않는다. 이미 했으면 건너뛴다.

`~/.claude/settings.json` 에 훅 넷을 건다. 형식은 `template/.claude/settings.json.tpl`.

| 이벤트 | matcher | 훅 |
|---|---|---|
| `PostToolUse` | `Write\|Edit` | `edit-check.mjs` |
| `PreToolUse` | `Write\|Edit\|Bash` | `guard-migrations.mjs` |
| `PreToolUse` | `Bash` | `commit-checklist.mjs` |
| `SessionStart` | — | `session-log.mjs` |

**사용자 레벨에 거는 이유**: 프로젝트의 `.claude/` 는 보통 git 밖이라, 프로젝트
레벨에 걸면 **워크트리에서는 훅이 존재하지 않는다** — 그리고 그 부재는 조용하다.
사용자 레벨이 안전한 이유는 훅이 첫 줄에서 파일 경로로 소관을 갈라 `skip` 하기 때문이다.

> **훅 이벤트 이름을 지어내지 마라.** 없는 이름으로 걸면 등록되고, 오류도 없고,
> 영원히 안 돈다. 실제로 `InstructionsLoaded` 라는 없는 이름으로 훅 하나가
> 오래 방치돼 있었다. 실재가 확인된 이름만 쓴다.

- **완료 판정:** 새 세션을 연 뒤 `~/.claude/harness-sessions.log` **파일이 생겼다.**
  등록했다는 사실로는 판정하지 않는다

## 1. 문서·설정을 놓는다

```bash
node <하네스>/scripts/apply-template.mjs <프로젝트> [--dry-run]
```

**있는 파일은 절대 덮지 않는다.** 이미 `AGENTS.md` 가 있고 내용이 다르면 멈추고
알린다(exit 1) — 말없이 덮으면 **시행 중인 규칙을 지우는 것**이다. 사람이 합친다.

`<하네스 경로>` 와 `<프로젝트 이름>` 자리표시자는 스크립트가 채운다.

- **완료 판정:** exit 0. 거부가 하나라도 있으면 **부분 적용이고, 부분 적용은 통과가 아니다**

### `--with` — 선택 디렉터리 둘

해당할 때만 붙인다. 빈 인덱스 표를 만들어 두면 **"아직 안 봤다" 와 "볼 게
없다" 가 구별되지 않는다.**

| | 무엇 | 수명 | git |
|---|---|---|---|
| `old/` | 이 프로젝트의 **과거 기획** | 옮기고 **지운다** | 넣는다 (옮긴 흔적이 diff 로) |
| `Reference/` | **외부** 재료 | 계속 둔다 | 뺀다 — **인덱스만** 커밋 |

`Reference/` 는 **재료지 근거가 아니다.** 보고 정했으면 `decisions/` 에
자기 말로 근거를 적는다. `.gitignore` 에는 **덧붙이기만** 하고 아무것도
지우지 않는다.

### 놓이는 것 = 적용 완료 형태

```
<프로젝트>/
├── AGENTS.md                       규칙의 진본
├── CLAUDE.md                       @AGENTS.md 한 줄
├── GEMINI.md                       포인터 한 줄
├── STATUS.md                       지금 상태
├── RUNBOOK.md                      명령
├── .cursor/rules/harness.mdc       포인터 한 줄
├── .claude/
│   ├── settings.local.json         model · claudeMdExcludes
│   ├── harness-budgets.json        문서 예산 (전부 3072)
│   └── rules/
│       ├── decisions.md            paths: 조건부 — 문서 쓸 때
│       └── verification.md         paths: 조건부 — 소스 건드릴 때
├── decisions/
│   ├── OPEN.md                     미결 등록부 — 열린 질문
│   └── _template.md                결정 서식
└── .git/hooks/{pre-commit,commit-msg}   ← 2단계에서
```

**일부러 놓지 않는 것** — 없는 것과 뺀 것은 다른 사실이라 적어 둔다.

| | 왜 |
|---|---|
| `decisions/README.md` | 결정이 10개를 넘을 때 만든다. 빈 라우팅 표는 읽는 비용만 낸다 |
| `.claude/settings.json` | 사용자 전역이다. 0단계에서 한 번 |

### 기획 단계면 선언한다

코드가 아직 없고 무엇을 만들지 고르는 중이면 `.claude/harness-gates.json` 에
`{ "stack": "none", "phase": "planning" }`. 그러면 `gates-report` 가 코드
게이트를 「해당 없음」으로 놓고 **기획 지표**(열린 질문 수 · 가장 오래된 것의
나이 · 닫힌 결정 수)를 보여 준다. **막지 않는다** — 며칠이 긴지는 도구가 모른다.

코드가 생기면 `phase` 줄을 지운다.

- **완료 판정:** `gates-report` 가 「기획 지표」를 찍는다.
  `decisions/OPEN.md` 가 없으면 exit 1 이다 — **미결을 담을 그릇이 없다는 뜻**

### `claudeMdExcludes` — 켤지 끌지 정한다

`.claude/settings.local.json` 에 기본값이 들어간다. **사용자 스코프 규칙에도
먹는 것이 확인됐다**(`docs/0a_claudeMdExcludes-검증.md`, 분기 A).

스택이 맞는 프로젝트에서는 오히려 켜 두는 것이 맞다 — 패턴을 프로젝트에 맞게 고친다.

- **완료 판정:** 0a 문서의 전사 확인 절차로 **실제 주입 목록**을 본다.
  설정에 적었다는 사실로 판정하지 마라 — 패턴 오타는 조용하다

## 2. git 훅을 건다

```bash
node <하네스>/adapters/git/install.mjs <프로젝트>
```

남의 훅이 이미 있으면 **거부하고 멈춘다**(exit 1). `--force` 는 사람이 내용을
보고 나서 쓴다.

이 계층은 **어느 에이전트든 돈다** — Codex·Gemini·손 커밋까지. 대신
`--no-verify` 로 뚫린다. 도구 계층(0단계)과 상보다.

- **완료 판정:** 열쇠말 없는 커밋을 실제로 시도해서 **막히는지 본다.**
  `src/` 를 건드리는 변경이 있어야 게이트가 켜진다

## 3. 완료 판정

```bash
node <하네스>/scripts/gates-report.mjs <프로젝트>
```

`exit 0` 이어야 끝이다. **여기까지 와야 이식이 끝난 것이다** — 파일을 놓았다는
사실도, 훅을 걸었다는 사실도 게이트가 돈다는 뜻이 아니다.

`★ 어느 계층에도 없다` 가 뜨면 그게 결손이다. 흔한 둘:

| 뜨는 것 | 뜻 | 할 일 |
|---|---|---|
| 「컴파일/타입 검사」 `★` + `스택을 알아보지 못했다` | 이 하네스가 모르는 스택이거나 빌드가 없다 | 빌드가 없으면 `.claude/harness-gates.json` 에 `{"stack":"none"}` 을 **선언**한다. 아니면 `core/editcheck.mjs` 에 구현을 붙인다 |
| 「컴파일/타입 검사」 `★` + `이 스택용 구현이 없다` | 스택은 알아봤는데 게이트가 없다 | `core/editcheck.mjs` 의 `HANDLERS` 에 한 줄. **짚어 놓고 방치하면 표만 늘어난다** |

> `해당 없음` 을 「없어도 되는 것」으로 읽지 마라. 표는 **필요한데 없는 것**만
> `★` 로 낸다. `stack:none` 선언이 있으면 그 사실을 그 자리에 적어 준다 —
> 사람이 정한 것과 도구가 못 찾은 것을 구별하기 위해서다.

## 4. 문서에 사실을 채운다

`apply-template` 이 놓은 `STATUS.md`·`RUNBOOK.md` 는 **빈 골격**이다.

- **완료 판정:** `STATUS.md` 의 「되는 것」에 **계획이 아니라 사실**이 적혀 있다.
  `node <하네스>/scripts/budget.mjs <프로젝트>` 가 exit 0

## 조건부 단계 — 해당할 때만

### 마이그레이션 보호

DB 마이그레이션(`db/migration/V*.sql`)을 쓰는 프로젝트에만 해당한다. 훅은 이미
0·2단계에서 걸렸으므로 추가 설치는 없다.

- **완료 판정 둘:** 커밋된 마이그레이션 편집이 **차단되고**, 아직 커밋 안 된
  새 마이그레이션 편집은 **통과한다.** 뒤쪽이 더 중요하다 — 거짓 차단이 잦으면
  사람이 게이트를 끄고, 꺼진 게이트는 없는 것보다 나쁘다(있다고 믿기 때문에)

### 픽스처 게이트

테스트가 버전관리 밖의 픽스처에 의존하면 만든다.

- 게이트 앞에 **이미 있는 삼킴부터 없앤다** — `catch (IOException) { return 빈값; }`
  같은 것이 있으면 게이트를 켜도 헛돈다
- **극성을 뒤집는다.** 기본을 required 로 두고 끄려면 환경변수를 명시하게.
  켜야 도는 게이트는 켜는 사람이 없어 존재하지 않는 것과 같다
- 테스트 러너가 **건너뛴 수를 마지막 줄에 크게 찍게** 한다

- **완료 판정:** 픽스처를 치우면 빌드가 **실패한다** (skip 이 아니다)

### 라우팅 점검

결정이 10개를 넘으면 `decisions/README.md` 를 만든다.

- **완료 판정:** `node <하네스>/scripts/routing-lint.mjs <프로젝트>/decisions/README.md` 가 0
