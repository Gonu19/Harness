# 0a. `claudeMdExcludes` 가 사용자 스코프 규칙에도 먹는가

> **왜 첫 단계인가.** 이 답에 따라 T-4(항상 켜진 외부 규칙 23.9KB)의 해법이 갈린다.
> 그리고 이건 **측정이 아니라 분기다** — "재 본다"로 끝나면 단계가 아니다.
> 결과별로 무엇을 할지 아래에 미리 적어 둔다.

## 무엇이 걸려 있나

`~/.claude/rules/ecc/common/*.md` 10개 + `README.md` = **23.9 KB**가
프론트매터가 없어 **매 세션 무조건** 컨텍스트에 실린다. 내용 상당수가
TypeScript·React 전제라 Java 저장소에는 한 줄도 적용되지 않는다.

공식 문서의 `claudeMdExcludes` 예시는 **프로젝트 트리의** 규칙 디렉터리를
제외한다. 사용자 스코프(`~/.claude/rules/`)에도 적용되는지는 명시가 없다.

## 검증 절차 (1분)

1. 대상 프로젝트에 `.claude/settings.local.json` 을 만든다 (이미 있으면 키만 추가):

```json
{
  "claudeMdExcludes": ["**/rules/ecc/common/**"]
}
```

2. **새 세션을 연다.** 설정은 세션 시작에 읽히므로 지금 세션에서는 안 바뀐다.

3. 새 세션에서 `/context` 를 실행하고 **Memory files** 목록을 본다.

## 판정

| 목록에서 | 뜻 | 다음 |
|---|---|---|
| `rules/ecc/common/*` 가 **사라졌다** | 사용자 스코프에도 먹는다 | **분기 A** |
| 그대로 **남아 있다** | 프로젝트 트리에만 먹는다 | **분기 B** |

## 분기 A — 먹는다

템플릿의 `.claude/settings.local.json` 에 `claudeMdExcludes` 를 표준 항목으로 넣는다.
프로젝트마다 안 맞는 외부 규칙을 골라 끄면 되고, **전역 설정을 건드리지 않으므로
다른 프로젝트에 영향이 없다.** T-4 는 여기서 닫힌다.

## 분기 B — 안 먹는다

프로젝트 쪽에서 끌 수 없으므로 **규칙의 위치를 옮기는 것**이 유일한 수단이다.
셋 중 하나를 고른다:

1. **`paths:` 를 붙인다.** `~/.claude/rules/ecc/common/*.md` 각 파일에
   프론트매터를 추가해 조건부로 만든다. 원본을 고치는 것이라
   ECC 를 갱신하면 날아간다 — 갱신 때 다시 붙이는 절차가 필요하다.
2. **`ecc-pruned/` 로 옮긴다.** 이미 에이전트 47개를 그렇게 격리해 둔 전례가 있다.
   가장 확실하지만 되돌리기가 수동이다.
3. **그대로 둔다.** 23.9KB ≈ 8K 토큰을 비용으로 받아들이고,
   대신 프로젝트 `CLAUDE.md` 에 무효화 선언을 둬서 **행동만** 고친다.
   토큰은 회수되지 않는다(오히려 2KB 늘어난다) — 이건 절약이 아니라 충돌 제거다.

> **어느 분기든 기록을 남긴다.** 결과를 이 파일 맨 아래에 한 줄로 적는다.
> 안 적으면 다음 프로젝트에서 같은 1분을 다시 쓴다.
